# Business Division / 事業部門向け Safety Status Report

# 本報告書の読み方について

本報告書では、GSN（Goal Structuring Notation）という手法を使って安全性の主張と根拠を整理している。文中に登場する記号の意味は以下の通りである：

- **G1〜G1.3等** = 安全目標（ゴール）：達成すべき安全性の目標
- **S1等** = 論証の方針（ストラテジー）：目標達成のアプローチ
- **Sn1〜Sn4等** = 安全性を裏付ける証拠（エビデンス）：目標達成を示す文書や記録
- **C1等** = 前提条件（コンテキスト）：論証の前提となる条件や規格

これらはGSNにおける管理番号である。GSNの知識がなくても、本文の説明に沿って読めば内容を理解できる構成となっている。

## 付録: 略語・用語集

| 略語・用語 | 正式名称・説明 |
|-----------|---------------|
| GSN | Goal Structuring Notation（安全論証の構造図） |
| ISO 26262 | 自動車機能安全規格 |
| HAZOP | Hazard and Operability Study（ハザード分析手法） |
| FTA | Fault Tree Analysis（故障の木解析） |
| UPS | Uninterruptible Power Supply（無停電電源装置） |
| KLOC | Kilo Lines of Code（1,000行のコード） |
| MS | Milestone（マイルストーン） |
| QA | Quality Assurance（品質保証） |
| PM | Project Manager（プロジェクトマネージャー） |

**GSN関連用語:**
- **ゴール（Goal, G）:** 達成すべき安全性の目標
- **ストラテジー（Strategy, S）:** 目標達成のアプローチ
- **エビデンス（Solution/Evidence, Sn）:** 目標達成を示す証拠
- **コンテキスト（Context, C）:** 論証の前提条件

**リスク・ハザード関連用語:**
- **ハザード:** 危険要因（システムが引き起こす可能性のある危険な状態）
- **リスク:** ハザードが実際に発生する可能性とその影響度
- **残存リスク:** 対策実施後に残るリスク
- **深刻度:** ハザードが発生した場合の影響の大きさ
- **発生頻度:** ハザードが発生する可能性の高さ
