# Product Division / 製品部門向け Safety Status Report

# 本報告書の読み方について

本報告書では、GSN（Goal Structuring Notation）という手法を使って安全性の主張と根拠を整理している。文中に登場する記号の意味は以下の通りである。

- **G1〜G1.3等** = 安全目標（ゴール）: システムが達成すべき安全性の目標
- **S1等** = 論証の方針（ストラテジー）: 安全目標をどのように達成するかの戦略
- **Sn1〜Sn4等** = 安全性を裏付ける証拠（エビデンス）: テスト結果や分析レポート等の具体的な証拠
- **C1等** = 前提条件（コンテキスト）: 安全論証が成立するための前提や適用範囲

これらはGSNにおける管理番号であり、安全論証の構造を追跡するために使用される。GSNの知識がなくても、本文の説明に沿って読めば内容を理解できる構成となっている。

## 1. G1: システムは安全に運用できる

### 1.1 安全目標の概要

**安全目標G1**は「システムは安全に運用できる」という本プロジェクトの最上位の安全主張である（文書ID: GSN-TEST-001）。この目標は、安全制御システムが実運用環境において、利用者や周辺環境に危害を及ぼすことなく動作することを保証するものである。

本目標は、自動車機能安全規格ISO 26262に準拠して開発されたシステムを対象としている（前提条件C1）。

### 1.2 達成状況と判断根拠

**達成状況:** 部分達成

**判断根拠:**
本目標の達成は、3つのサブゴール（G1.1、G1.2、G1.3）の達成状況に基づいて評価される。文書GSN-TEST-001の記載によると、以下の状況である。

- **G1.1（ハザード識別）:** 達成
- **G1.2（対策実施）:** 部分達成（対策完了率60%）
- **G1.3（要件検証）:** 部分達成（検証完了率60%）

3つのサブゴールのうち1つが達成、2つが部分達成であることから、トップゴールG1は「部分達成」と評価されている。

### 1.3 支持する下位ノードと論証構造

本目標は、以下の論証要素によって支持されている。

**論証戦略:**
- **S1:** ハザード分析による安全性論証（第2項参照）

**サブゴール:**
1. **G1.1:** すべてのハザードが識別されている（第3項参照）
2. **G1.2:** 識別されたハザードに対策が実施されている（第4項参照）
3. **G1.3:** 安全要件が検証されている（第5項参照）

**前提条件:**
- **C1:** ISO 26262準拠（第2.2項参照）

### 1.4 未解決の課題と論証ギャップ

文書GSN-TEST-001に記載された未解決事項は以下の通りである。

1. **H-104、H-105の対策完了が必要:** ハザードH-104（演算エラー）とH-105（通信途絶）の対策が未完了である
2. **SR-103、SR-105の検証完了が必要:** 安全要件SR-103（自己診断機能）とSR-105（異常検知機能）の検証が未完了である
3. **G1の再評価が必要:** 全サブゴール達成後に、2026年3月にGSN全体の再レビューを実施し、G1の達成を確認する予定である

これらの未解決事項により、現時点では「システムは安全に運用できる」という主張を完全には証明できていない状態である。

### 1.5 製品化への影響

**品質への影響:**
- 対策未完了のハザード2件（H-104、H-105）は、いずれもリスクレベルがMedium以下であり、Serious以上の高リスクハザードはすべて対策済みである（文書HAZ-TEST-001）
- 検証未完了の安全要件2件（SR-103、SR-105）は、いずれもASIL-B〜ASIL-Cであり、最高レベルのASIL-D要件は本プロジェクトに存在しない

**タイムラインへの影響:**
- 全サブゴールの達成目標は2026年2月末である（文書VRS-TEST-001）
- G1の再評価は2026年3月に予定されている（文書GSN-TEST-001）
- プロジェクト全体の進捗率は78%であり、計画比-5%の遅延が発生している（文書PSR-TEST-001）

## 2. S1: ハザード分析による安全性論証

### 2.1 論証戦略の概要

**論証戦略S1**は「ハザード分析による安全性論証」であり、トップゴールG1（システムは安全に運用できる）を達成するための方針を示している（文書GSN-TEST-001）。

この戦略は、ISO 26262に準拠したハザード分析アプローチを採用し、以下の3段階で安全性を論証する。

1. すべてのハザードを識別する（G1.1）
2. 識別されたハザードに対策を実施する（G1.2）
3. 安全要件を検証する（G1.3）

### 2.2 戦略の妥当性と有効性

**妥当性:**
文書GSN-TEST-001によると、本戦略は「ISO 26262に準拠したハザード分析アプローチを採用」しており、自動車機能安全規格に基づく標準的な論証手法である。

**有効性:**
文書GSN-TEST-001の記載によると、本戦略は「有効」と評価されている。この評価は、ISO 26262準拠という前提条件C1の成立に基づいている。

### 2.3 戦略の網羅性評価

本戦略は、ハザード識別→対策実施→検証という3段階のプロセスを網羅している。文書に記載された分解漏れや論証ギャップは以下の通りである。

**網羅されている要素:**
- ハザードの識別（G1.1、エビデンスSn1）
- 対策の実施（G1.2、エビデンスSn2）
- 要件の定義と検証（G1.3、エビデンスSn3、Sn4）

**【文書記載なし】:** 本戦略の分解が完全であるか、他の論証アプローチ（例: フォールトツリー分析単独、形式手法等）との比較優位性については、提供文書に記載されていない。

### 2.4 関連するコンテキストと前提条件

**C1: ISO 26262準拠**

本戦略は、システムがISO 26262（自動車機能安全規格）に準拠して開発されていることを前提としている（文書GSN-TEST-001）。

**前提の成立状況:**
文書SRS-TEST-001には「準拠規格: ISO 26262」と明記されており、安全要件仕様書がこの規格に基づいて作成されていることが確認できる。

**前提が崩れた場合の影響:**
【文書記載なし】ISO 26262準拠という前提が崩れた場合の安全論証への影響については、提供文書に記載されていない。

### 2.5 製品品質への寄与

本戦略により、以下の品質指標が達成されている（文書PSR-TEST-001、VRS-TEST-001）。

| 指標 | 実績 | 目標 | 状況 |
|------|------|------|------|
| テスト合格率 | 75% | 95% | 目標未達 |
| 不具合密度 | 0.8件/KLOC | 1.0件/KLOC以下 | 目標達成 |
| コードカバレッジ | 78% | 80% | 目標未達 |

テスト合格率とコードカバレッジが目標未達であることから、本戦略の実行は進行中であり、2026年2月末までの完了が計画されている。

## 3. G1.1: すべてのハザードが識別されている

**判断根拠:**

|------------|------|--------|----------|--------------|

### 3.4 ハザード識別の網羅性

**深刻度別の分布:**

文書HAZ-TEST-001によると、識別されたハザードの深刻度分類は以下の通りである。

| 深刻度 | 件数 | ハザードID |
|--------|------|------------|
| Catastrophic | 0件 | - |
| Critical | 0件 | - |
| Serious | 2件 | H-101, H-103 |
| Marginal | 2件 | H-102, H-104 |
| Minor | 1件 | H-105 |

Catastrophic（壊滅的）およびCritical（致命的）レベルのハザードは識別されていない。最も深刻なレベルはSerious（重大）であり、2件が該当する。

**【文書記載なし】:** ハザード識別の完全性（他に未識別のハザードが存在しないことの保証）については、提供文書に記載されていない。

### 3.5 製品品質への影響

本目標の達成により、以下の品質面での効果が得られている。

**リスクの可視化:**
5件のハザードが識別され、それぞれにリスクレベル（High/Medium/Low）が割り当てられている。これにより、対策の優先順位付けが可能となっている（文書HAZ-TEST-001、RS-TEST-001）。

**トレーサビリティの確保:**
