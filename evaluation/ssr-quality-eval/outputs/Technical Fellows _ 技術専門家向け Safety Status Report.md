## 3. 技術概要

### 3.1 システム目的と準拠規格

本システムは安全制御システムとして開発されており、ISO 26262（自動車機能安全規格）に準拠している（文書ID: GSN-TEST-001）。システムの主要目的は、異常検知時に安全状態への移行を保証することである。

### 3.2 技術選定根拠

**安全論証手法:**
- GSN（Goal Structuring Notation）を採用し、安全性を構造化された形式で論証
- ハザード分析手法としてHAZOPおよびFTAを採用（文書ID: HAZ-TEST-001）

**安全機構の設計判断:**
1. **冗長化設計（SR-104）:** 主要コンポーネント（センサー、制御ユニット、通信モジュール）を二重化し、単一故障点を排除
2. **緊急停止機能（SR-101）:** 異常検知時に500ms以内にシステムを安全状態に停止
3. **フェールセーフ機能（SR-102）:** 故障検知時に安全側に動作
4. **自己診断機能（SR-103）:** 起動時および定期的な自己診断により異常を早期検出
5. **異常検知機能（SR-105）:** センサー値の異常を100ms以内に検知

（出典: 文書ID: SRS-TEST-001）

## 7. 実装詳細

### 7.1 安全要件の実装状況

**SR-101: 緊急停止機能（ASIL-C）**
- 実装内容: 異常検知時に500ms以内にシステムを安全状態に停止
- 実装方式: オペレータによる手動停止と自動停止の両方をサポート
- 検証結果: 全20シナリオで合格、応答時間は平均320ms、最大450ms
- 技術的評価: 目標値（500ms以内）を達成しており、実装は妥当である

**SR-102: フェールセーフ機能（ASIL-B）**
- 実装内容: 故障検知時に安全側に動作
- 検証結果: フォールトインジェクションによる検証で全シナリオPASS
  - センサー故障シミュレーション: PASS
  - 通信途絶シミュレーション: PASS
  - 電源異常シミュレーション: PASS
- 技術的評価: 多様な故障モードに対して安全側動作が確認されており、実装は妥当である

**SR-103: 自己診断機能（ASIL-B）**
- 実装内容: 起動時および定期的な自己診断により異常を早期検出
- 検証結果: TR-103でFAIL（診断項目15件中12件PASS、3件不合格）
- 不合格項目の技術的詳細:
  1. メモリチェック: タイムアウト発生（原因: 診断対象メモリ領域の拡大）
  2. 通信診断: 一部ポート（Port 8080, 8443）で応答なし
  3. ログ出力: タイムスタンプフォーマットが仕様と不一致
- 是正措置: タイムアウト値調整（30秒→60秒）、ポート監視設定修正、ログフォーマット修正

**SR-104: 冗長化設計（ASIL-A）**
- 実装内容: 主要コンポーネント（センサー、制御ユニット、通信モジュール）を二重化
- 検証結果: TR-104で全項目PASS
  - プライマリ→セカンダリ切替: 200ms以内で完了
  - セカンダリ→プライマリ復帰: 正常動作確認
- 技術的評価: 設計レビュー2回実施、指摘事項3件はすべて対応済み

**SR-105: 異常検知機能（ASIL-C）**
- 実装内容: センサー値の異常（範囲外、急変、固着）を検知し、100ms以内に警告を発出
- 検証結果: 異常パターン8種類中5種類の検証完了、残り3種類は検証中
- 技術的評価: 検証完了パターンでは目標値（100ms以内）を達成しているが、全パターンの検証完了が必要である
